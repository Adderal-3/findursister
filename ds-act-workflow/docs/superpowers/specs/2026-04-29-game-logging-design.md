# 设计文档：模式5 — 游戏行为日志上报

**日期：** 2026-04-29  
**项目：** ds-act-skills  
**作者：** brainstorming session

---

## 背景

ds-act-skills 现有 4 个模式：接入大神功能、审查现有代码、构建并打包、接入微信小程序。

现有模式1注入的 `trackEvent` 是通用 NS 日志底层方法，支持 pageview、曝光、时长等通用日志。但游戏/活动业务层的关键行为（通关、获得奖励、失败等）需要开发者手动在业务代码中调用 `trackEvent`，目前没有工具支持。

`withPrecheck` 包裹了交互节点，但不打日志。模式2的点击预检也只检查是否包裹，不处理埋点。

---

## 目标

新增**模式5：游戏行为埋点**，面向非技术人员，扫描业务代码，语义识别游戏关键节点，生成并自动插入 `trackEvent` 调用。

---

## 节点分类

| 类型 | 说明 | 典型信号 |
|------|------|---------|
| **交互节点** | 关键按钮点击 | `withPrecheck` 包裹点、关键 click handler |
| **流程节点** | 游戏开始/重开 | 语义识别（开始、重开等） |
| **结果节点** | 通关、失败、超时 | 语义识别（胜利判断、gameOver 等） |
| **奖励节点** | 获得道具、领取奖励、兑换 | 语义识别（奖励回调、状态变更等） |

交互节点通过 `withPrecheck` 包裹点 + 关键点击语义识别；其余三类通过 LLM 语义分析业务代码识别。

---

## 流程设计

### 入口（模式选择菜单）

```
[5] 🎮 游戏行为埋点
    扫描业务代码，识别交互/流程/结果/奖励节点，生成 trackEvent 调用并插入
```

---

### 步骤1：前置检查

检查项目是否已接入 ds.js（即 `trackEvent` 可用）。

- ✅ 已接入 → 继续
- ❌ 未找到 ds.js → 阻断，提示：
  ```
  ❌ 未找到 ds.js，请先运行模式1完成基础接入后再使用游戏行为埋点功能
  ```

---

### 步骤2：扫描 + 语义识别

**扫描范围：**

| 框架 | 扫描范围 |
|------|---------|
| HTML | `src/` 下所有 `.js`、`.ts` 文件 + `index.html` 内联脚本；若无 `src/` 目录则扫当前目录（排除 `node_modules`、`.git`） |
| React | `src/` 下所有 `.js`、`.ts`、`.jsx`、`.tsx` 文件 |
| Vue | `src/` 下所有 `.js`、`.ts`、`.vue` 文件 |

**识别方式：** LLM 语义分析，识别四类节点。

**识别结果为空时：** 输出提示并退出：
```
未找到游戏行为节点。建议检查业务代码是否在扫描范围内，或手动在关键位置添加 trackEvent 调用。
```

**输出识别结果：**

```
## 游戏行为节点识别结果

| # | 位置 | 代码片段 | 节点类型 | 推荐 eventId | 推荐参数 |
|---|------|---------|---------|------------|---------|
| 1 | engine.js:45 | `withPrecheck(() => startGame())` | 交互 | `click_start` | `{}` |
| 2 | engine.js:120 | `if (score >= target)` | 结果-通关 | `game_win` | `{ score, level }` |
| 3 | api.js:88 | `onRewardSuccess(res)` | 奖励 | `get_reward` | `{ rewardId, count }` |
| 4 | game.js:200 | `gameOver()` | 结果-失败 | `game_over` | `{ score }` |

请选择需要埋点的节点（输入编号，如 1,2,3）：
💡 默认推荐：全部
```

用户输入编号后进入步骤3。

---

### 步骤3：展示示例 + 确认插入

对用户选择的每个节点，展示插入位置和代码示例。

**插入规则：埋点统一插在触发行之后**，确认事件已发生再上报，避免因后续逻辑错误导致误报。

```javascript
// engine.js:120 — 结果-通关
if (score >= target) {
  showWinScreen();
  trackEvent('game_win', { score, level }); // ← 新增，插在触发行之后
}
```

询问：
```
是否自动插入以上代码？
  [A] 全部插入
  [B] 选择性插入（逐个确认）
```

- 选 A：直接插入全部，进入步骤4
- 选 B：逐节点询问是否插入，收集确认列表后批量插入，进入步骤4

---

### 步骤4：插入完成报告

```
## 🎮 游戏行为埋点完成

| # | 位置 | eventId | 状态 |
|---|------|---------|------|
| 1 | engine.js:45 | click_start | ✅ 已插入 |
| 2 | engine.js:120 | game_win | ✅ 已插入 |
| 3 | api.js:88 | get_reward | ✅ 已插入 |
| 4 | game.js:200 | game_over | ⏭️ 已跳过 |

💡 验证方式：触发对应操作，在 NS 日志平台查询 EVENT_ACTION = [你的 EVENT_ACTION 配置值]
```

---

## 设计决策

| 决策 | 原因 |
|------|------|
| 语义识别而非关键词规则 | 游戏代码命名不统一，语义分析覆盖更全 |
| 不提供"只看示例"选项 | 面向非技术人员，强制走自动插入路径减少操作负担 |
| 交互节点也纳入，措辞与模式2明确区分 | `withPrecheck` 不打日志；用不同措辞（"是否已加埋点" vs "是否已包裹预检"）避免混淆 |
| 复用模式2扫描范围并扩展 | HTML 项目额外支持 `.ts`、内联脚本、无 `src/` 容错 |
| 前置检查 ds.js | 依赖 `trackEvent`，未接入则无法使用 |
| 埋点插在触发行之后 | 确认事件已发生再上报，避免误报；与 NS 日志惯例一致 |
| 识别为空时友好提示退出 | 面向非技术用户，静默失败不可接受 |
