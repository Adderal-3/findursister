# 公共表接入 · 第 3.5 步：生成 table.d.ts 类型声明

> 目标：把第 3 步 TableConfig JSON 里的表/字段/索引结构，转成一份 TypeScript 声明文件 `table.d.ts`，放在 `src/` 目录（与业务脚本 `game.js` / `game-common-table.js` 同级）。
> 前置：第 3 步 `validate.cjs` 已全绿。
> 后置：第 4 步生成 `game-common-table.js` 时，**必须重读本文件比对字段类型**，尤其 `STRING_LIST` 不能 `JSON.stringify`。

---

## 3.5.1 为什么是 .d.ts 而不是 .ts

| | `table.d.ts`（本 skill 采用） | `table.ts` |
|---|---|---|
| 语义 | TS 官方"纯类型声明"扩展名，天生就是"非可执行代码" | 普通可执行 TS 文件 |
| 构建工具 | 默认不编译、不打包、不扫描 | webpack/vite/esbuild 若配了 TS loader 可能误扫、误编译 |
| IDE | VS Code 自动加载，给 `.js` 文件提供 IntelliSense | 需显式 import 才生效 |
| 非 TS 项目 | 零风险 | 有风险（构建报错、类型检查失败） |

`.d.ts` 就是为"只作类型参考、不引入使用"这个场景设计的。项目不需要装 TypeScript、不需要配 tsconfig、不需要任何构建改动——文件放那儿就行，AI 读它比对类型，IDE 读它给提示。

---

## 3.5.2 生成规则

1. **文件位置**：`src/table.d.ts`（与业务脚本 `game.js` / `game-common-table.js` 同级）。若项目无 `src/`，则放项目根目录，与 `index.html` 同级。
2. **文件名固定** `table.d.ts`，不要起别的名字（AI 和 IDE 都按约定查找）。
3. **从第 3 步的 TableConfig JSON 逐表生成**，每张表一个 `interface`，字段名/类型/可选性严格对齐 `fieldType` + `nullable`。
4. **fieldType → TS 类型映射**：

   | TableConfig `fieldType` | TS 类型 | 说明 |
   |---|---|---|
   | `STRING` | `string` | 若存的是 JSON（对象/嵌套数组序列化后的字符串），TS 里可写成具体结构类型（如 `Skill[]`）并注明"存 STRING、写前 `JSON.stringify`、读后 `JSON.parse`" |
   | `NUMBER` | `number` | |
   | `BOOLEAN` | `boolean` | |
   | `STRING_LIST` | `string[]` | **数组，不是 string**；元素是**纯字符串**。写入直接传数组，读取直接用数组，**禁止 `JSON.stringify`/`JSON.parse`** |
   | `NUMBER_LIST` | `number[]` | 同上，禁止 stringify |
   | `BOOLEAN_LIST` | `boolean[]` | 同上，禁止 stringify |
   | `ENUM` | 字面量联合类型（如 `'A' \| 'B'`） | 取 `enumRules.allowedValues` |

> ⚠️ **datahub-table 没有 `OBJECT` 字段类型**（合法类型只有 `STRING`/`NUMBER`/`BOOLEAN`/`NULL`/`STRING_LIST`/`NUMBER_LIST`/`BOOLEAN_LIST`/`ENUM`，见 `01-table-design.md` 与 `validate.cjs`）。
> 要存**对象**或**对象数组**（如技能列表 `[{name,desc},...]`）时，**用 `STRING` 字段存 `JSON.stringify` 后的字符串**，读取后 `JSON.parse`（`stringRules.maxLength` 要留够，如 2000）。
> `STRING_LIST` 只能装**纯字符串数组**，装不下对象——把对象数组塞进 `STRING_LIST` 会被 `stringItemRules` 逐项校验拒绝（对象不是 string）。这是最容易踩的坑：`table.d.ts` 里这类字段务必标成具体结构类型（如 `Skill[]`）+ 注明"存 STRING/JSON"，**别标成 `string[]`**（那会被误当纯字符串数组直传）。

5. **nullable 处理**：`nullable: true` → 字段加 `?`（可选）；`nullable: false` → 必填。
6. **内置字段**：每张表都带 6 个系统自动补全的内置字段 + 主键 `_id`。为避免每个 interface 重复，抽出一个公共 `TableBuiltinFields` 基接口，各表 `extends` 它即可。类型/可选性严格照下表（`nullable: true` → 加 `?`）：

   | fieldKey | fieldType | TS 类型 | 含义 |
   |---|---|---|---|
   | `_id` | — | `string` | 记录主键（新增后由 `record._id` 返回） |
   | `__create_time` | NUMBER | `number` | 创建时间戳 |
   | `__update_time` | NUMBER | `number` | 更新时间戳 |
   | `__delete_time` | NUMBER | `number` | 逻辑删除时间，0=活跃 |
   | `__create_uid` | STRING | `string?` | 创建人 UID（nullable） |
   | `__delete_uid` | STRING | `string?` | 删除人 UID（nullable） |
   | `__under_review` | BOOLEAN | `boolean` | 审核状态 |
7. **导出方式**：用 `declare interface` 或 `export interface` 均可，推荐 `export interface`（IDE 跨文件识别更稳）。
8. **文件顶部注释**：写明"本文件为类型声明，非可执行代码，不需要 import；仅供 AI 生成读写代码时比对字段类型、IDE 提供 IntelliSense 用"。

## 3.5.3 模板

```typescript
/**
 * table.d.ts — 公共表（datahub-table）类型声明
 *
 * 本文件为 TypeScript 声明文件（.d.ts），非可执行代码：
 *   - 项目不需要安装 TypeScript、不需要 tsconfig、不需要任何构建改动
 *   - 不需要在任何 .js 文件里 import 本文件
 *   - 仅供 AI 生成 game-common-table.js 读写代码时比对字段类型
 *   - 仅供 IDE（VS Code 等）提供 IntelliSense
 *
 * 生成依据：第 3 步 TableConfig JSON（table-config.json）
 * 修改表结构后，必须同步更新本文件。
 */

/** 6 个系统内置字段 + 主键，所有表共有（服务端自动补全，配置里不写进 fields） */
export interface TableBuiltinFields {
  _id: string;             // 记录主键（新增后由 record._id 返回）
  __create_time: number;   // NUMBER, 创建时间戳
  __update_time: number;   // NUMBER, 更新时间戳
  __delete_time: number;   // NUMBER, 逻辑删除时间，0=活跃
  __create_uid?: string;   // STRING, nullable, 创建人 UID
  __delete_uid?: string;   // STRING, nullable, 删除人 UID
  __under_review: boolean; // BOOLEAN, 审核状态
}

/** 职业投稿 */
export interface PostsRecord extends TableBuiltinFields {
  faction: string;        // STRING, 阵营
  jobName: string;        // STRING, 职业名
  skills: string[];       // STRING_LIST, 技能列表 ← 数组！写入直接传数组，禁止 JSON.stringify
  jobBg?: string;         // STRING, nullable, 职业背景
  iconDesc?: string;      // STRING, nullable, 角色图标
  roleName?: string;      // STRING, nullable, 角色名
  nick?: string;          // STRING, nullable, 昵称
  avatar?: string;        // STRING, nullable, 头像
}

/** 投稿点赞 */
export interface PostLikesRecord extends TableBuiltinFields {
  postId: string;         // STRING, 投稿ID
}

/** 投稿评论 */
export interface PostCommentsRecord extends TableBuiltinFields {
  postId: string;         // STRING, 投稿ID
  text: string;           // STRING, 评论内容
  commentNick?: string;   // STRING, nullable, 评论者昵称
  commentAvatar?: string; // STRING, nullable, 评论者头像
}
```

> 以上为**示例结构**，Agent 须根据第 3 步实际锁定的表/字段生成，禁止照抄示例表名。

## 3.5.4 生成后的自检

生成 `table.d.ts` 后，立即自检：

1. **每个 `STRING_LIST`/`NUMBER_LIST` 字段对应 TS 类型是数组**（`string[]`/`number[]`），不是 `string`。← 这是本次新增本步骤的核心动机
2. **每个 `nullable: true` 字段有 `?`**，`nullable: false` 没有。
3. **每张表都 `extends TableBuiltinFields`**，且该基接口含全部 6 个内置字段 + `_id`：`__create_time`/`__update_time`/`__delete_time`（`number`）、`__create_uid`/`__delete_uid`（`string?`）、`__under_review`（`boolean`）、`_id`（`string`）。
4. **字段名与 TableConfig JSON 的 `fieldKey` 完全一致**（大小写、下划线）。

自检通过后进入第 4 步代码生成。
