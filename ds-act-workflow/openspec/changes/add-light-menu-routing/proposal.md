## Why

当前 SKILL.md 路由采用"直接匹配即执行"——用户输入编号或能力名时 agent 立即执行，跳过展示能力全貌的机会。新用户不知道 skill 提供哪些能力、不知道典型执行顺序；单能力执行完就停，用户需反复回忆下一步。同时能力注册表 `[5] 持久化` 依赖列写"无"，实际服务端存储与公共表依赖 `[1] 注入大神` 提供的登录态——是错误声明。

## What Changes

- **新增能力菜单展示**：触发 skill 后向用户展示能力全貌（编号/能力/一句话 + 推荐路径），让用户看到有哪些能力、当前已具备哪些。首次触发或意图不明确时展示；用户明确指定能力时可直接执行，不强制每次弹菜单。
- **新增链式推荐**：主流程能力执行完成后重新展示菜单并推荐下一步。推荐是提示不是限制，用户可偏离。
- **修正 [5] 持久化依赖**：注册表"依赖"列从"无"改为"本地无 / 服务端+公共表需 [1]"——服务端存储与公共表依赖 [1] 提供的登录态。

## Capabilities

### New Capabilities

- `menu-routing`：能力菜单展示 + 链式推荐。轻量设计——菜单有条件展示（非每次强制），状态仅标"已具备"二态，推荐一句话不穷举场景，菜单模板作示例非 MUST。

### Modified Capabilities

无 spec 层级需求变更。[5] 依赖修正属注册表元数据修正，不改 `server-storage-mission-module` 现有需求。

## Impact

- `SKILL.md`：新增"能力菜单展示"+"能力执行后推荐"两小节；能力注册表 [5] 依赖列修正。
- `references/capabilities/game-storage.md`：依赖段补充服务端/公共表对 [1] 登录态的依赖。
- `CONTEXT.md`：加"能力菜单展示""链式推荐"两术语。
- `openspec/specs/menu-routing/spec.md`：新增能力规范（归档时同步）。
- `evals/evals.json`：新增 eval 覆盖菜单展示与链式推荐。

## Non-Goals

- 不做状态推断规则表（4 态枚举 + 13 行规则）——agent 根据依赖列 + 扫描结果自然判断，状态仅标"已具备"。
- 不做单选契约死规则（多输入取第一个 + 固定提示语）——agent 自然处理。
- 不做交互措辞规定（"你选择了[X]，即将执行"标注、无法识别输入固定提示、退出流程）。
- 不做菜单格式 MUST（四列固定 + 顺序不可颠倒）——模板作示例。
- 不做推荐场景穷举（7 类）——推荐路径一行 + 一句话。
