## ADDED Requirements

### Requirement: 能力菜单展示

Skill SHALL 在依赖检测 + 前置扫描完成后、能力路由匹配之前，向用户展示能力菜单。菜单 MUST 包含能力清单（编号/能力/一句话）+ 推荐路径行。用户明确指定能力（编号或名称）时 MAY 直接执行，MUST NOT 强制每次展示菜单。菜单状态列仅标 `✅ 已具备`（前置扫描检测到该能力产物），其余不标。非 Cocos 项目 MUST NOT 显示 `[C]` 行。菜单展示 MUST NOT 触发 tool call（仅输出文本）。

#### Scenario: 首次触发展示菜单

- **WHEN** 用户触发 skill 且未通过依赖/扫描门禁失败，且用户未明确指定能力
- **THEN** agent 展示菜单，含能力清单 + 推荐路径行
- **AND** agent 等待用户选择，MUST NOT 自动执行

#### Scenario: 用户明确指定能力时不强制弹菜单

- **WHEN** 用户输入"模式1" / "1" / "注入大神"
- **THEN** agent MAY 直接执行该能力，MUST NOT 强制先弹菜单
- **AND** 首次或项目状态变化时仍可展示菜单辅助决策

#### Scenario: 状态列仅标已具备

- **WHEN** agent 展示菜单
- **THEN** 仅对前置扫描检测到产物的能力标 `✅ 已具备`
- **AND** 其余能力状态列留空，agent 根据依赖列自然判断

---

### Requirement: 能力执行后行为按进入方式区分

能力执行完成后的行为按用户进入方式区分：通过模式编号/能力名进入的，完成后重新展示菜单 + 推荐推荐路径里的下一步；单能力意图驱动的，完成后重新展示菜单供继续选择，不主动推荐；组合意图驱动的，完成后只输出状态摘要，不弹菜单，用户主动继续时再展示。`[7]` 开发服务器与 `[C]` Cocos 是工具能力，MUST NOT 强制推荐下一步。

#### Scenario: 模式进入完成后链式推荐

- **WHEN** 用户通过模式编号/能力名进入某能力，且该能力执行完成
- **THEN** agent 重新展示菜单 + 推荐路径里的下一步

#### Scenario: 单能力意图驱动完成后出菜单不推荐

- **WHEN** 用户通过单能力意图驱动（如"帮我接入分享"）进入，且能力执行完成
- **THEN** agent 重新展示菜单供继续选择
- **AND** MUST NOT 主动推荐下一步

#### Scenario: 组合意图驱动完成后只出摘要

- **WHEN** 用户通过组合意图驱动（如"打包上线"→audit+deploy）进入，且组合执行完成
- **THEN** agent 只输出状态摘要
- **AND** MUST NOT 弹菜单，用户主动继续时再展示

#### Scenario: 工具能力不强制推荐

- **WHEN** [7] 或 [C] 执行完成
- **THEN** agent MUST NOT 强制推荐下一步，由用户主动选择

---

### Requirement: [5] 持久化依赖修正

`SKILL.md` 能力注册表 `[5] 持久化` 的依赖列 SHALL 按子选项声明，MUST NOT 声明整体为"无"。本地存档 → 无依赖；服务端存储 + 公共表 → 依赖 `[1] 注入大神`。

#### Scenario: 注册表依赖列按子选项标注

- **WHEN** 用户查阅 SKILL.md 能力注册表
- **THEN** [5] 行依赖列 MUST 展示"本地无 / 服务端+公共表需 [1]"
- **AND** MUST NOT 出现整体"无"声明
