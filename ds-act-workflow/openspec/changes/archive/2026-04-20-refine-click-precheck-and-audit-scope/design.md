## Context

ds-act-skills 是网易大神运营活动 H5 的业务注入与审查工具，支持 HTML/React/Vue 三种技术栈。当前存在两个核心问题：

1. **注入模式**：步骤 0 扫描所有点击事件后，步骤 6 无差别全部用 `withPrecheck` 包裹。但 `withPrecheck` 会做"App 外拉起 APP + App 内未登录弹登录页"两步预检，纯 UI 交互（关闭弹窗、切换 Tab、查看规则）不需要也不应该被包裹。
2. **审查模式**：步骤 1 只列出 DS 注入文件，但 audit-rules.md 中的"重复逻辑检测"和"CLICK-PRECHECK 块"规则需要扫描业务代码才能执行，导致规则与执行不一致。

## Goals / Non-Goals

**Goals:**
- 注入时让用户选择哪些点击事件需要 `withPrecheck` 包裹，而非全部自动包裹
- 提供启发式标注辅助用户快速判断（🔴建议包裹/🟢可不包裹/🟡需确认）
- 审查模式能实际执行重复逻辑检测和点击预检检查（全局扫描业务代码）
- 审查规则与审查执行保持一致

**Non-Goals:**
- 不改变 `withPrecheck` 函数本身的逻辑
- 不改变 DS 注入文件的生成模板（SDK-LOADER、ds.js、hooks/composables 内容不变）
- 不引入新的 DS marker（如 PRECHECK-TARGETS）
- 不做自动化测试框架的搭建

## Decisions

### 决策 1：点击事件分类使用启发式标注 + 用户交互选择

**选择**：注入步骤 0 扫描点击事件后，根据按钮名/变量名启发式标注建议级别，然后让用户选择哪些需要包裹。

**替代方案**：
- A) 全部自动包裹（当前方案）→ 体验差，纯 UI 点击被错误包裹
- B) 在 ds.js 中记录预检清单 marker → 增加维护成本，且项目可能已变更
- C) 审查时重新扫描 + 交互确认 → 审查阶段可行，但注入阶段也应该让用户选择

**理由**：方案 A 已证明有问题；方案 B 增加了 marker 复杂度；注入时就让用户选择是最自然的时机，审查时再重新扫描确认即可。

**启发式规则**：

| 信号模式 | 标注 |
|---------|------|
| 名称含 `start`/`play`/`begin`/`draw`/`lottery`/`claim`/`exchange`/`share`/`submit`/`confirm`/`join`/`enter` | 🔴 建议包裹 |
| 名称含 `close`/`cancel`/`tab`/`toggle`/`rule`/`rules`/`back`/`arrow`/`prev`/`next`/`scroll`/`hide`/`show` | 🟢 可不包裹 |
| 无法匹配 | 🟡 需确认 |

### 决策 2：审查模式采用"DS 文件精确审查 + 全局扫描补充"双轨制

**选择**：审查步骤 1 保持 DS 注入文件列表用于 Marker 结构校验，同时增加"全局扫描"步骤用于重复逻辑检测和点击预检检查。

**理由**：
- Marker 结构校验（SDK-LOADER、CONFIG、JSSDK 等）只需检查 DS 注入文件
- 重复逻辑检测和点击预检检查必须扫描业务代码
- 两种审查的文件范围不同，不应混为一谈

**审查流程调整**：
```
步骤 1：确定审查目标文件（DS 注入文件 + ds.d.ts）
步骤 2：DS Marker 结构校验（仅检查 DS 注入文件）
步骤 3：JSSDK 深度校验
步骤 4：HTML 安全审查
步骤 4.5（新增）：全局业务代码扫描
  - 重复逻辑检测（扫描全部业务代码）
  - 点击预检检查（扫描全部业务代码，列出已包裹/未包裹状态，用户确认）
步骤 5：输出审查报告
```

### 决策 3：审查时点击预检检查采用"重新扫描 + 交互确认"方案

**选择**：审查时重新扫描全局点击事件，列出已包裹/未包裹状态，让用户确认未包裹的是否应该包裹。

**理由**：
- 不引入新 marker，保持简洁
- 项目可能在注入后已变更，需要重新评估
- 审查本来就是交互式过程（安全审查也是）

## Risks / Trade-offs

- [启发式标注可能误判] → 标注只是建议，最终由用户决定；🟡需确认的项确保不会遗漏
- [审查时全局扫描可能较慢] → 只扫描点击事件模式和重复函数名，不做全量 AST 分析
- [用户可能跳过选择直接全选] → 默认推荐🔴项被选中，用户可调整
- [React/Vue 项目业务代码文件较多] → 限制扫描范围为 src/ 目录下的 .js/.ts/.jsx/.tsx/.vue 文件
