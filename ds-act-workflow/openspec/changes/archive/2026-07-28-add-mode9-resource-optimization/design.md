## Context

运营项目暴露图片资源偏大无门禁覆盖。MR !39 加了 deploy 软门禁体积警告（只警告不处理）。运营要手动压缩（tinypng/资产管理），门槛高。需要 mode 9 资源优化能力自动压缩 + 去重。

现有能力 0/C/1-8，mode 9 是新增。门禁 vs 能力边界（CONTEXT.md 定义）：门禁不可跳过，能力可选。压缩有损该 opt-in，归能力。架构决策见 ADR-0004，技术选型见 ADR-0005。

## Goals / Non-Goals

**Goals:**
- mode 9 用 sharp 压缩 `src/assets/` 下 >300KB 图片源文件（只压质量不 resize，保持原格式）
- 内容 hash 去重避免重复压缩累积质量损失
- 压缩前告知运营确认（有损操作）
- 压缩后内部 vite build 验证没破坏构建
- deploy 软门禁 A 形态引导（门禁检测大图 → 引导执行 mode 9）
- `.compress-cache.json` 进 git 团队共享

**Non-Goals:**
- 不自动 resize（尺寸难定，破坏设计意图）
- 不转 webp（兼容性零风险，保原格式）
- 不重压到达标（重压会糊，压完仍超阈接受+告知）
- 不改 deploy 门禁为硬阻断（体积阈值难统一，软警告不阻断）
- 不压缩音频/视频（本能力聚焦图片，音频/视频后续）

## Decisions

1. **归能力不归门禁**（ADR-0004）：门禁不可跳过 vs 压缩有损 opt-in，矛盾。归能力，用户选择执行。
2. **A 形态衔接**（ADR-0004）：deploy 软门禁检测大图引导执行 mode 9，不自动压缩。
3. **改源文件不压产物**（ADR-0004）：产物 gitignored 无法 git 提交持久；改源文件一次永久小，Git 门禁基线可回退。
4. **告知确认**（ADR-0004）：有损操作值得一次确认（mode 8 添加遮罩有先例）。
5. **sharp 工具**（ADR-0005）：本地免费离线，直接压源文件（vite 插件压产物不匹配）。
6. **保持原格式**（ADR-0005）：大神 App WebView 版本不确定，保 png/jpeg/gif 兼容性零风险。
7. **不 resize**（ADR-0005）：尺寸难定，破坏设计意图。png 大图压完仍超阈走接受+告知。
8. **内容 hash 去重**（ADR-0005）：sharp 每次压质量有损，重复压累积损失。内容 hash 匹配则跳过。
9. **.compress-cache.json 进 git**（ADR-0005）：项目资源处理状态团队共享，区别 .skill-cache.json 本地环境状态 gitignore。避免跨人重复压缩。
10. **压后仍超阈接受+告知**（ADR-0005）：重压会糊，300KB 是软门禁阈值不是硬律。长图超阈合理。
11. **内部 build 验证**：压缩改二进制可能损坏，vite build 验证没破坏 H1。
12. **>300KB 阈值**：和 deploy 软门禁一致，跨文件不漂移。
13. **mode 9 编号**：独立新能力，编号顺延（现有 0/C/1-8）。

## Risks / Trade-offs

- **sharp native 依赖**：C++ binding，预编译 binary 大部分平台 OK，极端环境可能要编译。风险低（运营标准 Node 环境）。
- **png 压缩空间有限**：png 无损格式，sharp 压质量对 png 效果不如 jpeg。2.5MB png 压完可能仍超阈。缓解：走接受+告知，运营拆图/换素材。
- **有损不可逆**：压缩改源文件，原始高清版丢失。缓解：Git 门禁基线保护可回退 + 压缩前告知确认。
- **cache 进 git 噪音**：cache 更改产生提交。缓解：在能力提交内，无额外噪音。
