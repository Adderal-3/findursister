> 本文档取代 v1.x《理论满分（TheoryMax）》：**星锚由「匀速满分模型」更换为「极限速点模型」**；旧 f(n) 降级为「节奏参考」（见 §一.3），不再参与星级线计算。

## 一、背景：为什么换锚

### 1.1 D9 裁决（v2.4 已定稿）

**连击无时间窗口，仅点错清零**（无尽模式跨波保留连击）。只要玩家不点错，第 i 次命中的倍率恒为 m_i = 1 + 0.1×(min(i,10)−1)，与两次命中之间隔多久无关。

### 1.2 旧 f(n) 匀速模型为什么不能再当星锚

旧模型假设「匀速命中」：第 i 次命中发生在 t_i = i×T/(n+1)，满分 = T×f(n)。它在 v2.3 审查中被证实**两个方向同时崩坏**（详见《玩法文档审查报告》🔴-1/🔴-2，本文数值均为 v2.4 参数下复核）：

- **内伤——模型与连击规则自相矛盾。** 匀速模型的命中间隔 = T/(n+1)。v2.4 参数（T = half-up((45+8n)×coef)，Boss 系数已按 D18 改 0.9）复核全 100 关：间隔最小的 L20 Boss 关（n=36，T=300）也有 **8.11s**，第 1 关（n=3，T=69）17.25s，极速关（n=2，T=31）10.33s——**全表 > 3.5s**。也就是说：只要规则里存在任何 ≤3.5s 的连击窗口，文档自己的「完美玩家」从第 2 击起连击全断，「满连击满分」根本不存在。这是 D9 取消时间窗口的直接原因。
- **外伤——无窗口后旧锚不是上界，三星批发。** D9 裁决后，剩余时间与连击数两个因子被「尽早连续命中」同时最大化，速点成为支配策略。v2.4 参数复核全 100 关：极限速点得分（即本文 StarBase）是旧锚 T×f(n) 的 **2.019~2.204 倍**、旧三星线（旧锚×75%）的 **2.691~2.939 倍**。典型值：L1 2.050 倍 / 2.733 倍；n=12 标准关 2.201 倍 / 2.934 倍；极速关 2.019 倍 / 2.691 倍。「理论满分」被真实打法翻倍碾压，星级线形同虚设（审查实测：极速关旧三星线 24.0，随手 49 分即三星；四道星门余量 2~4 倍）。

### 1.3 旧 f(n) 的新角色：节奏参考

f(n) 不再担任星锚，但保留为**节奏参考**——它描述「把全程时间匀速摊完」打法的得分，用于玩家画像与配速推演（本文 §六 配速对照表的「匀速」行即用它）。闭式备查（与求和式逐项一致）：

```
n ≤ 10：  f(n) = n/2 + n×(n−1)/60
n ≥ 10：  f(n) = 29/2 + [ 19×(n−10)×(n−9) − 1760 ] / [ 20×(n+1) ]
```

（例：f(12) = 8.169231。f(n) 与 T 的换算、取整等工程细节不再赘述——它已不进任何线上公式。）

## 三、推导：从求和式到 StarBase = T×M(n) − 0.4×h(n)

### 3.1 求和式

由 A1/A2，第 i 次命中：剩余时间 r_i = T − 0.4×(i−1)，倍率 m_i = 1 + 0.1×(min(i,10)−1)，单次得分 s_i = r_i × m_i（保底 1 分规则在模型内永不触发，证明见 §八.1）：

```
StarBase(n,T) = Σ_{i=1..n} [ T − 0.4×(i−1) ] × m_i
              = T × Σ_{i=1..n} m_i  −  0.4 × Σ_{i=1..n} (i−1)×m_i
              = T × M(n) − 0.4 × h(n)
```

其中 **M(n)（倍率和）** 与 **h(n)（加权位移和）** 都只与 n 有关。

### 3.2 M(n) 闭式推导

```
n ≤ 10：M(n) = Σ [1 + 0.1(i−1)] = n + 0.1 × n(n−1)/2 = n + 0.05n(n−1) = 0.9n + 0.05n(n+1)
n ≥ 10：M(n) = M(10) + 1.9×(n−10) = 14.5 + 1.9×(n−10)
```

两式在 n = 10 处衔接（均为 14.5）。

### 3.3 h(n) 闭式推导

注意位移权重是 (i−1)（第 1 击 t=0 无位移）：

```
h(n) = Σ (i−1)×[1 + 0.1(i−1)] = Σ(i−1) + 0.1×Σ(i−1)²
     = n(n−1)/2 + 0.1 × (n−1)n(2n−1)/6
     = n(n−1)/2 + n(n−1)(2n−1)/60
```

把 n(n−1)/2 拆成 0.45n(n−1) + 0.05n(n−1)，后者并入第二项：0.05n(n−1) + n(n−1)(2n−1)/60 = n(n−1)(2n+2)/60 = n(n²−1)/30，得契约闭式：

```
n ≤ 10：  h(n) = 0.45n(n−1) + n(n²−1)/30
n ≥ 10：  h(n) = h(10) + Σ_{i=11..n} (i−1)×1.9 = 73.5 + 1.9×[n(n−1)/2 − 45] = 0.95n(n−1) − 12
```

两式在 n = 10 处衔接（均为 73.5）。

## 四、StarBase 公式与星级线规则（D10）

```
StarBase(n,T) = T × M(n) − 0.4 × h(n)
⭐      过关即得（找齐全部目标）
⭐⭐    得分 ≥ floor(StarBase × 55%, 0.1)
⭐⭐⭐  得分 ≥ floor(StarBase × 75%, 0.1)
```

**取整规则**：向下取整到 0.1 分，实现为 `Math.floor(x*10 + 1e-6) / 10`——`+1e-6` 抵消二进制浮点误差（如 212.5 存为 212.49999999999 时被误判为 212.4）。取整方向向下，保证线不会被浮点「顶高」造成「看着到了却没给星」。

## 六、玩家配速对照表（L16：n = 12，T = 141）

**实战配速模型**：配速 p = 平均每个目标 p 秒（第 1 个目标也要 p 秒），第 i 击 t_i = p×i，零失误满连击。则

```
score(p) = Σ (T − p×i)×m_i = T×M(n) − p × Σ i×m_i = T×M(n) − p×[h(n) + M(n)]
```

（恒等式：Σ i×m_i = Σ(i−1)m_i + Σ m_i = h(n) + M(n)。L16：h+M = 113.4+18.3 = 131.7，score(p) = 2580.3 − 131.7p。）

基准：StarBase = 2534.94，⭐⭐ 线 1394.2，⭐⭐⭐ 线 1901.2。

## 七、工程实现

### 7.1 JS 伪代码（O(1) 闭式，推荐）

```js
// 倍率和 M(n)：m_i = 1 + 0.1*(min(i,10)-1) 的前 n 项和
function M(n) {
  return n <= 10 ? 0.9*n + 0.05*n*(n+1)
                 : 14.5 + 1.9*(n - 10);
}

// 加权位移和 h(n)：Σ_{i=1..n} (i-1)*m_i
function H(n) {
  return n <= 10 ? 0.45*n*(n-1) + n*(n*n - 1)/30
                 : 0.95*n*(n-1) - 12;
}

// 星锚基准分（D10）；T = half-up((45+8n)*coef)，必须先取整再代入
function starBase(n, T) {
  return T*M(n) - 0.4*H(n);
}

// 向下取整到 0.1；+1e-6 抵消二进制浮点误差（如 212.49999999999 被误判为 212.4）
function floor01(x) {
  return Math.floor(x*10 + 1e-6) / 10;
}

function starLines(n, T) {
  const sb = starBase(n, T);
  return { star2: floor01(sb*0.55), star3: floor01(sb*0.75) };
}
```

### 7.2 为什么不再需要一维查表

旧模型 TheoryMax = T×f(n) 能预生成 60 行一维表，是因为匀速假设下每次命中的剩余时间**全部正比于 T**，T 可整体提出，f(n) 只依赖 n。新模型 StarBase = T×M(n) − 0.4×h(n) 中，位移项 0.4×h(n) **与 T 无关**，T 无法提出为整体因子——StarBase 是 (n, T) 的二元函数。二维查表（60 × 数百种 T）既臃肿又无必要：M/h 闭式是 O(1) 精确计算，直接内联即可。

### 7.3 测试基准（CI 交叉断言）

用求和式作为闭式的单元测试基准（n=1..60 全量断言，误差 = 0，分数运算）：

```python
from fractions import Fraction as Fr
def m(i):  return Fr(10 + min(i,10) - 1, 10)
def M(n):  return sum(m(i) for i in range(1, n+1))
def H(n):  return sum(Fr(i-1)*m(i) for i in range(1, n+1))
def star_base(n, T):  return T*M(n) - Fr(4,10)*H(n)
# 锚点断言：star_base(3,69)=226.3；star_base(12,141)=2534.94；star_base(2,31)=64.66
```

## 八、边界情况与维护规则

### 8.1 「保底 1 分」规则对星锚无影响

契约规定单次命中保底 1 分。模型内得分最低的是最后一击：s_n = (T − 0.4×(n−1)) × m_n。穷举验证（n = 1..60 × 全部 6 种类型系数，T 取 v2.4 时间公式 half-up 值）：最低值 27.00 分（理论极值 n=1 极速，T=27）≫ 1 分；实表最低（n=2 极速关 T=31）s_2 = 30.6×1.1 = 33.66 分。

结论：模型内任意一击得分都远高于 1 分，保底规则永不触发，**StarBase 不需要任何修正**。保底只兜实战「拖到读秒才命中」的零分挫败。

### 8.2 沙漏 / 视频加时为什么不计入星锚

1. **定义层面**：星锚是「裸关基准线」（A4/A5），用途是让星级线对所有玩家、所有重玩稳定可比。沙漏与视频都固定 +15s，但是否使用、使用几次仍属于玩家局内行为；计入后基准线会随行为变化，星级评价失去统一锚点。
2. **机制层面**：加时抬高后续命中的剩余时间，使实际得分**可以超过 StarBase**——这是道具/视频入口的存在意义（付费与留存价值），不是公式漏洞。
3. 星级线永远按裸关 T（half-up 取整后）计算；加时只在「实际得分」侧生效。冻结怀表（计时停 5s）同理。

### 8.3 适用范围

本模型只服务**闯关 100 关的星级线**。无尽模式无星级（时间银行计分，命中得分 = 当前剩余时间 × 倍率，无尽榜吃图鉴+伙伴加成）；UGC 关卡成绩不计入任何榜单与招募条件（D19），均不使用本文星线。

### 8.4 改参数时的重算步骤

| 改动 | 影响面 | 动作 |
|---|---|---|
| 改倍率（步长 0.1 / 封顶位置 min(i,10) / 封顶值） | **M(n)、h(n) 全表失效** | 改求和式 → 重推闭式 → n=1..60 交叉断言 → 全关星线重算 |
| 改物理上限 0.4s/个 | M/h 不变，StarBase 位移系数变 | 只改 `starBase` 中的 0.4 → 全关星线重算 |
| 改时间公式 / 类型系数（D18） | M/h 不变，逐关 T 变 | T 重算（half-up）→ 逐关 StarBase 与星线重算 |
| 改 55% / 75% | 只变星线 | 只改 `starLines` |

重算脚本（改完参数直接跑，先断言再输出）：

```python
from fractions import Fraction as Fr
def m(i):  return Fr(10 + min(i,10) - 1, 10)          # 按新契约改这一行
def M(n):  return sum(m(i) for i in range(1, n+1))
def H(n):  return sum(Fr(i-1)*m(i) for i in range(1, n+1))
def M_c(n): return Fr(9,10)*n + Fr(5,100)*n*(n+1) if n<=10 else Fr(145,10) + Fr(19,10)*(n-10)
def H_c(n): return Fr(45,100)*n*(n-1) + Fr(1,30)*n*(n*n-1) if n<=10 else Fr(95,100)*n*(n-1) - 12
for n in range(1, 61):
    assert M(n) == M_c(n) and H(n) == H_c(n)           # 闭式改了也要同步改这里
for n in range(1, 61):
    print(n, f"{float(M(n)):.4f}", f"{float(H(n)):.4f}")
```
