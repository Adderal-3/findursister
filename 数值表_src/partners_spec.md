# 伙伴招募条件精确规格（partners_spec）

> 版本：v1.5 · 对应《玩法设计文档》v3.5 §5.2、§3.2、附录 B（含决议 D13/D15/D17/D22/D26/D30/D31）
> 读者：开发。目标是「照着写代码不需要再问任何问题」。
> 范围：8 位伙伴的招募条件、追踪指标（localStorage 键）、判定时机、进度显示、文案、加成结算口径。
> 代码状态（2026-07-24）：`src/game/partners.ts`、`src/components/HomePanels.tsx`、`src/components/PartnerRecruitDialog.tsx` 已实现 8 位伙伴条件、存档、小屋、进度、招募队列与总榜加成；未获得伙伴不显示姓名与头像，获得后才使用 `huoban/` 源头像文件名对应的原名。

当前静态 H5 的实现适配：

- `onlineTick` 与有效游玩计时按 5 秒内存/写盘周期推进，精度高于规格建议的 30 秒；切后台不累计。
- 当前没有独立签到系统；8 个现行招募条件均不依赖签到。
- 123 件内容没有旧版六主题字段；叶雪青的“自然发现”由植物、动物、飞行，以及花、昆虫、水果、蔬菜标签实时派生。
- 招募加成已用于本地榜分与 DataHub 写榜；正式公平榜仍需由可信服务校验关卡成绩、伙伴条件与招募结果。
- 完整敲门→开门→翻牌序列仍属于表现层待办；当前以队列庆祝弹窗保证不打断局内。

## 0. 全局口径（先读这里，所有伙伴共用）

### 0.1 术语

| 术语 | 定义 |
|---|---|
| **基础分** | 单关结算总分，**不含**伙伴系数。星级判定、单关 ≥1500 条件、每关历史最高分存储，一律用基础分口径 |
| **累计型条件** | 指标单调递增（只增不减），当前值 ≥ 阈值即达标，如「累计在线 30 分钟」 |
| **单次型条件** | 指标为「历史最好成绩」，某一局打出 ≥ 阈值的成绩即达标，如「单局 8 连击」 |
| **单日达成型条件** | 单次型的子类：指标每日 0 点重置，**任意一天**当日值 ≥ 阈值即达标；每日重置指标只允许用于此类条件（见 §5 无掉队设计原则），如「单日累计游玩 20 分钟」 |
| **羁绊型条件** | 不占常规判定，监听其余 7 人全部招募完成事件自动加入（仅姬蜜儿） |
| **单关标准榜分** | `round(min(1.2, 单关历史最高原始分 / starBase) × 1000)`；单关封顶 1200 |
| **总榜口径** | `round(所有关卡历史最高标准榜分之和 ×（1 + 伙伴加成）)`；隐藏发现记录不参与加成 |
| **日榜口径** | 当日各关最高标准榜分之和，每关每日只计一次最好成绩；**不吃伙伴加成**（D13） |

### 0.2 判定检查点（Trigger）

每次下列任一事件发生，统一遍历**所有未招募伙伴**（姬蜜儿除外）检查一次条件，达标即招募；一次检查多人达标则按 partnerId 顺序排队依次播放招募动画：

| 检查点 ID | 触发时机 | 说明 |
|---|---|---|
| `settle` | 闯关模式找齐目标成功结算，或无尽模式整局结束 | 闯关超时失败局不写入伙伴指标、也不触发条件判定；UGC 结算不进入伙伴系统（D19） |
| `discover` | 隐藏首次发现入账时（首次找到某物品） | 只服务叶雪青条件；不展示公开图鉴或数量 |
| `onlineTick` | 在线计时节流写盘时（每 30 s，见 §3 `znm.prog.onlineSec`） | **补充检查点**：否则纯挂机不结算的玩家永远招不到 1 号叶问舟 |
| `launch` | 应用启动进入主界面时 | **兜底检查点**：容错补发；若上次退出前已达标未弹窗，启动时补触发 |

姬蜜儿（`meimei`）**不参与**上述遍历，单独监听「已招募名册变更」事件：每次有伙伴招募成功后，检查其余 7 人是否齐，齐则立即自动招募姬蜜儿（见 §4-6）。

### 0.3 判定伪代码

```ts
const ALL7 = ['afu','xixi','gugu','yuanyuan','paopao','xingxing','mimi']; // 不含 meimei

function checkPartners(trigger: 'settle'|'discover'|'onlineTick'|'launch') {
  const recruited: string[] = loadJson('znm.partner.recruited', []);
  const pendings: string[] = [];
  for (const p of PARTNERS) {                       // PARTNERS 按 §1 顺序，meimei 不在其中
    if (recruited.includes(p.id)) continue;
    if (p.readMetric() >= p.threshold) pendings.push(p.id);
  }
  for (const id of pendings) recruit(id);           // recruit 内部见下
}

function recruit(id: string) {
  const recruited = loadJson('znm.partner.recruited', []);
  if (recruited.includes(id)) return;               // 幂等，防重复
  recruited.push(id);
  saveJson('znm.partner.recruited', recruited);
  const at = loadJson('znm.partner.recruitedAt', {});
  at[id] = Date.now();
  saveJson('znm.partner.recruitedAt', at);
  enqueueRecruitPopup(id);                          // 进弹窗队列，依次播放 §2 文案
  // 姬蜜儿监听：名册每次变更后执行
  if (ALL7.every(x => recruited.includes(x))) recruit('meimei');
}
```

局内（关卡进行中）达标**不打断游戏**：所有招募动画只在结算页 / 返回主界面后播放；弹窗队列存于内存即可，无需持久化（`launch` 兜底检查保证不丢）。

### 0.4 进度显示通用规则

- 未招募位：伙伴小屋中只显示**获得方式 + 进度条 + 进度文本**，不渲染姓名或头像（各伙伴文本格式见 §2）。
- 进度条比例 = `min(当前值 / 阈值, 1)`；文本中的当前值**封顶显示**（超过阈值也只显示阈值，如「在线 30/30 分钟」），直到招募完成再揭示姓名和头像。
- 点击未招募卡：弹出通用获得方式说明，不在解锁前泄露伙伴身份。
- 招募成功：播敲门 → 开门 → 翻牌动画 + §2 各卡「招募成功弹窗文案」，并弹字「🤝 +1.25%」（姬蜜儿为「🤝 +1.25% · 满员 +10% 达成！」）。

## 3. 行为指标字典表

localStorage 键名沿用现有 `znm.*` 点分前缀风格（现有：`znm.best.levels` / `znm.best.endless` / `znm.best.maxLevel`）。除注明「依赖键」外，均由伙伴系统（建议 `partners.ts`）负责读写。

| metricKey | 数据类型 | 含义 | 更新时机（写入事件） | 每日重置 | 边界规则 |
|---|---|---|---|---|---|
| `znm.prog.onlineSec` | number（整数秒，≥0） | 累计在线时长 | 页面激活状态下每 **30 s** 节流累加写盘一次；`visibilitychange → hidden` 与 `pagehide` 时把未写盘余额 flush | 否 | 仅 `document.visibilityState === 'visible'` 时计时（含菜单/结算/游戏内暂停，与现有暂停逻辑一致）；切后台即停、回前台续计；跨天不清零；写盘动作同时触发 `onlineTick` 检查点 |
| `znm.prog.dailyPlaySec` | number（整数秒，0~86400） | **当日**累计有效游玩秒数（燕无归条件专用） | 闯关/无尽进行中由 `playTick` 节流累加写盘（建议每 30 s 一次）；关卡结束、暂停切后台、`pagehide` 时把未写盘余额 flush；UGC 不计 | **是，每日 0 点重置为 0** | 仅闯关/无尽实际游玩中计时：菜单、结算页、UGC、伙伴小屋等不计；暂停不计，切后台即停。demo 用本地日期，正式版使用服务器配置时区。与 `onlineSec` 独立写盘互不回填 |
| `znm.prog.dailyPlayDate` | string，`YYYY-MM-DD`（本地时区） | `dailyPlaySec` 归属日期（重置判定的辅助键） | 与 `dailyPlaySec` 同一次写入 | 否 | 用本地时区生成（勿用 UTC）；必须与 `dailyPlaySec` 同事务写入；玩家改系统时间不回扣当日进度（防作弊底线见设计文档 §7） |

## 4. 边界情况细则（必须按此实现）

1. **签到以本地自然日切换为准**：本地时间 0 点跨天即视为新一天，当天首次启动记 1 天；同一天多次启动只记 1 天；**不要求连续**（断签不清零、不回退）。判定完全依赖 `znm.prog.signInLastDate` 字符串比较，不做时间戳差值计算（避免 23:59→00:01 之类误差）。
2. **三星关数按「历史最高星级」累计，只增不减**：某关曾达 ⭐⭐⭐ 即永久计入 `threeStarLevels`；之后重玩该关只得 1 星**不会**把计数打回去。数据源是每关最高星级表 `znm.best.levelStars` 的派生统计，不写独立累加器。
3. **8 连击指有效单局最大连击数**：仅闯关成功局和完整无尽局可更新 `znm.prog.bestCombo`；闯关失败局与 UGC 按 D19 隔离。点错清零只清当局当前连击，不清当局已达到的临时最大值。
4. **累计找物 500 件含同物品重复找到**：`znm.prog.totalFound` 按「命中次数」计，不按品种去重；同一个西红柿在 500 次命中里出现 50 次就计 50。与隐藏首次发现列表（按品种去重）是两套独立口径。
5. **单关得分 ≥ 1500 按「基础分」判定**：比较值为结算时的基础分（§0.1），**不含伙伴系数**——防止伙伴加成把未达标基础分膨胀后白送招募。进度显示同理用基础分。
6. **姬蜜儿不占常规判定**：`meimei` 不出现在 §0.3 的伙伴遍历表 `PARTNERS` 中；她的唯一入口是 `recruit()` 内的名册监听——任何伙伴招募成功后检查其余 7 人是否齐，齐则同帧自动招募姬蜜儿（`launch` 兜底检查同样适用）。姬蜜儿自身计入 8 人上限，同样提供 +1.25%。
7. **加时机满格截断不影响得分口径**：时光沙漏加时不超过本关总时长（满格截断）；加时后命中的得分仍是基础分，正常参与 `bestBaseScore` 与星级判定。
8. **存储容错**：所有 `znm.*` 读取必须做解析容错（缺失 / 非数字 / JSON 解析失败一律按 0 / 空值处理），不得因脏数据导致判定崩溃或误招募。
9. **多人同时达标**：一次检查点若多人达标，按 §1 表 # 顺序排队，逐个播放招募动画；姬蜜儿若也因此触发，永远排在最后。
10. **单日游玩 1200 秒按「当日值」判定，每日 0 点重置**：`znm.prog.dailyPlaySec` 只计关卡实际游玩（不含菜单/结算/暂停）；本地时间 0 点跨天即归零（读写前比较 `dailyPlayDate` 字符串，同 §4-1 口径）。跨天对局处理：一局跨越 0 点时，0 点前已写盘的秒数留在旧日，0 点后余额计入新日（以写盘时刻的日期归属为准，不做局内拆账）。**达标前进度每天归零是预期行为**——该条件为「单日达成型」，任意一天打满 20 分钟即可，违反此重置语义（如做成跨天累计）反而违反 §5 无掉队原则的指标用途约束。

## 5. 无掉队设计原则（对应决议 D15）

> 本条是对**全部 8 个伙伴招募条件**的硬性约束，新增/修改任何条件前必须先过本节核验。

### 5.1 原则条文

1. **不得以自然日累计为门槛**：任何与奖励/伙伴/榜单挂钩的永久进度，不得要求「累计 N 个自然日」「连续 N 天」之类的日历门槛；所有条件必须能通过**任意日期的行为**补足进度——晚入坑、断档再回归的玩家，永远可以用后续行为追齐，不存在「错过就永远补不回」的进度。
2. **每日重置的指标只允许用于「单日达成型」条件**：指标每日 0 点清零时，其服务的条件必须是「任意一天当日值 ≥ 阈值即达标」（如燕无归的单日游玩 1200 秒），不得用于跨天累计型判定。每日上限/每日重置仅可用于**消耗品防刷**（如眼力值每日补满、分享得眼力日限 3 次），不得用于伙伴进度门槛。
3. **进度永不可逆扣**：除「单日达成型」指标的每日重置外，任何伙伴进度指标只增不减（历史最好成绩、累计计数、点亮名册均不回退），重玩掉星、断签、点错清连击均不影响已累积的进度。

### 5.2 八个条件逐一合规核验

| # | 伙伴 | 条件 | 指标性质 | 是否自然日门槛 | 核验结论 |
|---|---|---|---|---|---|
| 1 | 叶问舟 | 累计在线 1800 秒 | 永久累计，跨天不清零 | 否，任意日期在线均可补足 | ✅ 合规 |
| 2 | 燕无归 | 单日累计游玩 ≥ 1200 秒，任意一天达成 | 每日重置指标，但属**单日达成型**（§5.1-2 唯一允许用途） | 否，不要求累计天数、不要求连续，任意一天打满即可 | ✅ 合规 |
| 3 | 叶雪青 | 自然物品发现 15 种 | 永久累计，只增不减 | 否，任意日期发现均可补足 | ✅ 合规 |
| 4 | 方承意 | 10 关历史最高 ⭐⭐⭐ | 永久累计（历史最高派生），掉星不回扣 | 否，回炉旧关刷星任意日期有效 | ✅ 合规 |
| 5 | 阿初 | 累计找到 500 件 | 永久累计，只增不减 | 否，任意日期寻物均可补足 | ✅ 合规 |
| 6 | 花将离 | 单关基础分 ≥ 1500 | 历史最好成绩，永久保留 | 否，任意一天打出即永久达标 | ✅ 合规 |
| 7 | 无情 | 单局 8 连击 | 历史最好成绩，永久保留 | 否，任意模式任意一天打出即永久达标 | ✅ 合规 |
| 8 | 姬蜜儿 | 其余 7 人全部招募 | 名册监听，依赖项全部合规 | 否 | ✅ 合规（随 1~7 号合规而合规） |

> 注：燕无归的条件曾使用「累计签到 2 天」，v2.4 起按 D15 替换为「单日游玩 20 分钟」。签到指标不再作为任何伙伴招募条件。

## 6. 伙伴加成结算规则

| 规则 | 精确口径 |
|---|---|
| 加成数值 | 伙伴加成 = 已招募人数 × **1.25%**；系数 = `1 + 0.0125 × n`，n ∈ 0..8；满 8 人 = **+10%**（×1.10） |
| 生效时点 | **获得时点起生效**：伙伴系数不做快照，在每次总榜读取/结算时按**当前**已招募人数实时计算；因此招募成功瞬间，总榜立即按新系数重算并体现，无需重玩旧关 |
| 生效范围 | **当前总榜**；日榜 = 当日各关最高标准榜分之和，永远不含伙伴系数（D13/D30） |
| 最终公式 | `round(各关历史最高标准榜分合计 ×（1 + 伙伴加成）)`；隐藏首次发现记录不参与榜单加成 |
| 存储分层 | 每关历史最高分、单关 ≥1500 判定、星级判定一律存/用**基础分**；伙伴系数只在榜单展示与写榜时套用，不回写关卡最高分 |
| 写榜分层 | `levels_daily_score` = 当日标准榜分；`levels_total_score` = 最终总榜分；`levels_base_score` = 未加成标准分合计；`partner_bonus_bps` = 伙伴加成基点（每位 125） |
| 展示 | 结算页与排行榜显示最终榜分、基础分合计和伙伴加成；本关结算另显示本局分、原历史最好与入榜增量 |
